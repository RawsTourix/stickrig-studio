# 07. Работа с ИИ, API и MCP

> Цель — чтобы нейросеть могла **создавать и редактировать структурированные элементы**, а автор — свободно менять результат вручную. MCP — лишь один из транспортов; работа редактора не должна от него зависеть.

## Разделить формат и протокол

1. **Формат проекта:** какие именно объекты, слои, позы, дорожки и сцены существуют.
2. **Команды доменного ядра:** что можно прочитать/изменить с проверкой, историей действий и стабильными ID.
3. **CLI/локальный API:** программный доступ без GUI и без ИИ.
4. **MCP-сервер:** адаптер, предоставляющий некоторые команды MCP-клиенту при наличии совместимого подключения.

Даже если MCP недоступен в определённом клиенте, JSON и локальные команды остаются полезными.

## Что делегировать ИИ

Подходящие задачи:
- Создать тренировочный зал из векторных линий, дверей, лестницы и перекрытий.
- Сгенерировать вариант помещения и расставить декорации за пределами кадра.
- Создать шаблон простого оружия или другого предмета с якорем `grip`.
- Раскрасить противников и привести цвета к согласованной палитре.
- Создать/изменить группы, слои и повторяемые элементы.
- Проверить проект на невидимые объекты, нарушения ссылок и проблемы композиции.
- Предложить последовательность действий, не внося изменения без запроса.

На первых этапах **позы, действия и драматургия боя** создаются человеком. ИИ не должен автоматически менять их, когда его попросили только нарисовать фон.

## Возможный набор команд

| Команда | Назначение |
| --- | --- |
| `get_project_summary` | Метаданные, сцены, объекты, выбранный кадр |
| `list_assets` / `get_asset` | Библиотека фигур и доступные свойства |
| `get_scene` | Структура сцены без обязательной передачи всех медиа |
| `list_layers` | Слои и их статусы |
| `create_asset` | Новый проверенный шаблон |
| `add_entity` | Новый объект из шаблона или примитива |
| `update_properties` | Выборочное изменение свойств по ID |
| `set_keyframe` | Изменение позиции/позы/камеры в заданном кадре |
| `apply_batch` | Атомарная группа операций, preview/dry-run |
| `render_preview` | PNG предпросмотра заданного кадра/камеры |
| `validate_project` | Структурная проверка без изменений |

Фактические MCP-имена, JSON Schema аргументов и ответы будут закреплены после реализации соответствующих команд ядра.

## Пример пользовательского сценария

Пользователь: «Нарисуй двухэтажный зал: белый фон, тонкие чёрные контуры, лестница справа, двери по бокам. Персонажей не трогай».

1. ИИ запрашивает структуру сцены и допустимые примитивы.
2. Создаёт план изменений **только фоновых слоёв**.
3. Система валидирует операции и показывает перечень изменений (dry-run).
4. По команде автора операции применяются одной транзакцией.
5. `render_preview` возвращает изображение результата.
6. Автор или ИИ по запросу корректирует геометрию.
7. Любую операцию можно отменить без затрагивания поз персонажей.

## Пример транзакции (концептуальный)

```json
{
  "scene_id": "scene-hall",
  "base_revision": 12,
  "dry_run": true,
  "operations": [
    {
      "op": "add_shape",
      "layer_id": "layer-bg",
      "shape": {
        "type": "line",
        "from": [0, 540],
        "to": [920, 540],
        "stroke": "#202020"
      }
    },
    {
      "op": "add_shape",
      "layer_id": "layer-bg",
      "shape": {
        "type": "rectangle",
        "origin": [100, 300],
        "size": [120, 240],
        "stroke": "#202020"
      }
    }
  ]
}
```

Это **иллюстрация интерфейса**, а не действующий API. `base_revision` нужен, чтобы операция не применялась молча к уже изменившейся сцене.

## Предпросмотр как цикл обратной связи

Без изображения ИИ знает координаты, но может плохо оценивать композицию. Поэтому планируется возможность получить PNG сцены с заданной камерой/кадром и метаданными. Это дополняет JSON, а не заменяет его: обратное превращение плоской картинки в редактируемые объекты не требуется.

Возможен предпросмотр **до применения** изменений в изолированной копии сцены.

## Безопасность и контроль

- Локальная работа по умолчанию; включение внешнего доступа — отдельное осознанное действие.
- Только разрешённые команды, без исполнения произвольного Python/командной строки из проекта или MCP-запроса.
- Чтение может быть доступно отдельно от прав на запись.
- На изменения — подтверждение пользователя или явно доверенный локальный режим.
- Группы изменений ограничиваются по числу операций, размеру, длительности и диапазону объектов.
- Права на конкретные сцены и слои; запрет менять защищённые объекты.
- `dry_run`/предпросмотр и история/undo; изменения целиком атомарны.
- Проверка идентификаторов, координат и путей медиа; защита от traversal/zip-архивов.
- Нельзя доверять инструкциям, спрятанным в пользовательских asset-файлах, описаниях или сторонних данных.
- Не предоставлять сетевой интерфейс без продуманной аутентификации, авторизации и оценки рисков.

## Транспорты и подключение

MCP поддерживает обмен структурированными инструментами; возможны локальные и сетевые варианты транспорта. Для первой интеграции разумно рассмотреть **локальный stdio**; сетевой транспорт требует отдельного проектирования безопасности и совместимости.

**Совместимость с конкретным клиентом ChatGPT или другим ИИ не гарантируется самим фактом наличия MCP-сервера.** Понадобится проверить доступные способы подключения и ограничения клиентской среды.

Документация протокола: [Model Context Protocol](https://modelcontextprotocol.io/introduction), [спецификация](https://modelcontextprotocol.io/specification/latest).

## Этапность

1. Закрепить и тестировать JSON-формат.
2. Сделать доменные операции и CLI без GUI.
3. Реализовать безопасный выборочный патч по ID.
4. Реализовать PNG-предпросмотр и dry-run.
5. Подключить MCP-адаптер.
6. Протестировать диалог «создай фон → посмотри результат → уточни → прими».

**Критерий успеха:** ИИ создаёт окружение, которое сразу можно вручную изменить, не трогая существующие кадры с анимацией персонажей.
