# 17. Исправление независимости кадров и порога перетаскивания (v0.4.2)

> Статус: реализовано в коде и протестировано в headless Qt; ручной тест Windows требуется.

## Проблема, выявленная на Windows

Пользователь добавил линии и стикмена на разные кадры, но ранее созданные элементы появлялись на последующих. Система смешивала *покадровый рисунок* с *постоянным содержимым сцены*: примитивы автоматически помещались в слой `background`, а стикмены наследовали видимость между кадрами. Даже `+` мог оставлять видимыми фоновые примитивы. Это противоречит ожиданию редактора покадровой анимации.

При перетаскивании центральной карточки вверх иногда начинал двигаться нижний кадр: критерий назначения был связан с точкой указателя и пересчитывался на границах списка, а не с положением самой захваченной карточки.

## Правила v0.4.2

- **Новый объект принадлежит одному кадру** через необязательное `entity.frame_index`, 0-based. Новые стикмены и примитивы из GUI получают его автоматически. Отдельного фонового режима в UI пока нет.
- **Добавить пустой `+`:** `insert_blank_frame` не копирует ни одного frame-local объекта. Для старых глобальных объектов вставляет ключи невидимости на новом кадре и восстанавливает значение на следующем. **Пустой действительно пуст**, включая старые объекты `background`.
- **Дублировать кадр:** `insert_frame` независимо копирует относящиеся к кадру объекты, выдаёт новые ID и переносит вычисленную позу стикмена. Изменение фигуры в копии не изменяет фигуру в оригинале. Старые hold-треки unscoped объектов продолжают работать как раньше.
- **Перенести кадр:** `move_frame` перемещает вместе с позой все привязанные `frame_index`; другие кадры остаются неизменными.
- **Удалить кадр:** удаляет его локальные сущности и связанные дорожки, а индексы последующих кадров сдвигает. Undo/Redo работает через прежнюю историю.
- **Выделение:** при переходе на кадр без выбранного объекта выделение снимается. Нельзя редактировать отсутствующий на данном кадре объект через устаревший Inspector.
- **Рендер:** холст, миниатюры, PNG и MP4 используют одну фильтрацию видимости; не существует «дублирования» объекта только в экспорте.
- **CLI/ИИ:** `add_shape` и `add_stickman` поддерживают `frame`, по умолчанию 0, и создают локальные объекты. Для намеренно постоянного элемента можно передать `persistent: true`; это не поведение по умолчанию.

## Почему нет автоматической миграции старых проектов

Ранние JSON могли хранить линии как `background`, а персонажей — как глобальные entities с hold-ключами. В них **не записан первоначальный кадр создания**. Автоматически назначить таким объектам один кадр — значит догадаться и потенциально испортить существующую анимацию.

Поэтому `frame_index` — необязательное поле. Его отсутствие означает прежнее поведение ради совместимости. Для уже сохранённых проектов нужна отдельная осознанная миграция с резервной копией, когда будут утверждены правила. Новое поведение следует проверить на **новом проекте**.

Также различать:
- **onion skin:** полупрозрачный контур предыдущего кадра в редакторе, не объект текущего кадра;
- **hover preview:** полупрозрачная модель под курсором, ещё не добавленная на сцену.

## Перетаскивание

Позиция вставки теперь меняется только когда **центр плавающей карточки** пересекает центр соседней карточки с порогом 8 px. Для обратного движения применяется небольшая зона гистерезиса; захват за разные точки ручки не меняет семантику, поскольку учитывается относительная точка захвата.

До пересечения порога **ни один соседний кадр не двигается**. Если второй кадр тащить вверх, сдвигается верхний, а не нижний. Анимация, маркер и сохранение модели остаются неразрушающими, и перемещение выполняется единожды после drop.

## Проверка

1. Создать новый проект. Нарисовать линию на кадре 1, нажать `+`. На кадре 2 ничего не должно быть.
2. На кадре 2 нарисовать круг, нажать `+`. На кадре 3 пусто; добавить стикмена.
3. Убедиться по трём миниатюрам и экспортным изображениям, что каждый кадр содержит **только свой** объект.
4. Дублировать кадр 2, изменить круг в копии. Оригинальный круг должен остаться прежним.
5. Переставить кадры и удалить один. Содержание других не должно изменяться.
6. Захватить средний кадр за правую ручку, двигать вверх **не доходя до середины верхнего**: другие карточки остаются на месте. Перейти за порог: только верхняя карточка раздвигается.
7. Сохранить и загрузить проект; затем проверить Ctrl+Z/Ctrl+Y.

Отдельно проверить сценарий с предыдущей версией JSON; не применять безоговорочную миграцию.
