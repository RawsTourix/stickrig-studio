# 05. Открытый формат проекта (черновик)

> **Обновление v0.1:** ниже описано исходное целевое направление формата, а не точная текущая схема. Для реально реализованных полей и ограничений прототипа см. [11 — Prototype v0.1](11-prototype-v0.1.md). Действующий v0.1 поддерживает одну сцену, базовый rig, простые примитивы и `hold`-ключи.

> **Не утверждённая спецификация**. JSON ниже — пример целевой структуры для согласования с реализацией. Синтаксис и имена полей могут поменяться до первой версии схемы.

## Требования к формату

1. **Читаемость человеком и машиной:** JSON, стабильные понятные имена полей, единицы измерения.
2. **Единый источник истины:** GUI и API используют один объектный граф.
3. **Структурность:** сцены, слои, шаблоны, экземпляры, дорожки свойств и монтаж разделены.
4. **Переиспользование:** один asset может иметь много scene instances.
5. **Без лишних копий:** не сериализовать весь фон или всю фигуру в каждом кадре.
6. **Предсказуемость:** порядок слоёв и keyframes явно определён.
7. **Безопасность:** вложенные пути ограничены проектом; данные не выполняются как скрипты.
8. **Версионирование:** `schema_version` + миграции и проверка при загрузке.

## Предполагаемое размещение

Во время разработки удобно работать с папкой:

```text
my-animation/
├── project.json          # метаданные, сцены, экземпляры и анимационные каналы
├── assets/
│   ├── stickman.json      # определение скелета и внешнего вида
│   └── katana.json        # пользовательский предмет
├── media/
│   ├── music.ogg          # необязательно; по лицензии пользователя
│   └── effects.wav
└── thumbnails/            # необязательный кэш, не источник истины
```

Позднее эту папку можно упаковывать в архив с отдельным расширением (например, `.stickrig`), не теряя возможности редактировать файлы. Точное расширение и политика встраивания внешних ресурсов — открытое решение.

## Пример `project.json`

```json
{
  "format": "stickrig-project",
  "schema_version": 1,
  "project_id": "demo-training-hall",
  "name": "Training hall demo",
  "settings": {
    "fps": { "numerator": 24, "denominator": 1 },
    "resolution": { "width": 1920, "height": 1080 }
  },
  "assets": [
    {
      "id": "asset-basic-stickman",
      "kind": "rig",
      "path": "assets/stickman.json"
    }
  ],
  "scenes": [
    {
      "id": "scene-hall",
      "name": "Hall",
      "duration_frames": 72,
      "layers": [
        { "id": "layer-bg", "name": "Background", "order": 0, "locked": false, "visible": true },
        { "id": "layer-actors", "name": "Actors", "order": 1, "locked": false, "visible": true }
      ],
      "entities": [
        {
          "id": "floor",
          "kind": "line",
          "layer_id": "layer-bg",
          "geometry": { "from": [0, 900], "to": [1920, 900] },
          "style": { "stroke": "#202020", "stroke_width": 5 }
        },
        {
          "id": "hero",
          "kind": "rig_instance",
          "asset_id": "asset-basic-stickman",
          "layer_id": "layer-actors",
          "transform": { "position": [450, 760], "rotation_deg": 0, "scale": [1, 1] }
        }
      ],
      "camera": {
        "base": { "center": [960, 540], "zoom": 1 }
      },
      "tracks": [
        {
          "target_id": "hero",
          "property": "transform.position",
          "keyframes": [
            { "frame": 0, "value": [450, 760], "interpolation": "hold" },
            { "frame": 24, "value": [850, 760], "interpolation": "hold" }
          ]
        },
        {
          "target_id": "hero",
          "property": "pose.elbow_left.rotation_deg",
          "keyframes": [
            { "frame": 0, "value": 0, "interpolation": "hold" },
            { "frame": 12, "value": -45, "interpolation": "hold" }
          ]
        }
      ]
    }
  ]
}
```

Здесь предполагается, что `assets/stickman.json` содержит сустав с ID `elbow_left`. В полном формате описанию требуются точные правила пространства координат, порядок наложения каналов и разрешение ключей; пример не заменяет валидатор.

## Координаты и единицы

- Мировые координаты 2D — числа с плавающей точкой в условных единицах; по умолчанию `+X` вправо, `+Y` вниз.
- Экспортное разрешение — пиксели, но геометрия сцены не обязана ограничиваться кадром.
- Повороты — градусы, с единой заранее закреплённой ориентацией.
- Временные позиции — целые `frame`, от нуля, `duration_frames` задаёт длину сцены.
- FPS — рациональное число, чтобы точно поддерживать 24, 25, 30 и дробные стандарты.
- Сериализатор должен иметь правила округления и устойчивые численные допуски.

## Семантика сцены

- У сущности постоянный `id` в пределах сцены.
- У шаблона — постоянный `asset id` в пределах проекта/библиотеки.
- `entity.layer_id` ссылается на существующий слой.
- Ссылка `asset_id` обязательна для экземпляра шаблона.
- Дорожка определяет значения одного свойства; несуществующие цели/пути — ошибка валидации.
- Ключи одного канала сортируются по `frame` и не дублируют одну позицию.
- Если до первого ключа нет записанного значения, используется исходное значение экземпляра или rig.
- При `hold` значение сохраняется до следующего ключа; интерполяция необязательна.
- Камера хранится отдельно от zoom/scroll состояния UI.

## Дальнейшее расширение

В перспективе добавить:
- `attachments` (предмет ↔ кисть, интервал действия);
- `constraints` (ограничение суставов и шарниров);
- `camera.tracks` (анимация камеры);
- `montage` (клипы сцен, аудио, дорожки и переходы);
- библиотечные `asset_version` и override-поля экземпляров;
- `project_metadata`, лицензии медиа, пользовательские заметки.

## Надёжность файлов

- Нельзя загружать произвольные пути за пределами каталога проекта через `../`.
- При открытии архива — ограничивать размер и количество файлов, избегать Zip Slip.
- Проверять структуру и версии *до* изменения текущего проекта.
- Сохранять во временный файл и атомарно заменять оригинал после успешной проверки.
- Не выполнять команды/скрипты, полученные из JSON, SVG или сетевого ответа.
- Старые версии проекта мигрировать контролируемо, с резервной копией.

**Следующий практический шаг:** перед написанием основного UI закрепить минимальную версию схемы и тесты round-trip (`load → save → load`), ссылочной целостности и воспроизводимого рендера.


## Замечание по прототипу v0.4.2 (не финальная схема)

В реализуемом прототипе у новой фигуры или примитива есть необязательное целочисленное `frame_index` (номер кадра, начиная с 0). Наличие поля ограничивает видимость и редактирование одним кадром. Например:

```json
{
  "id": "line-example",
  "kind": "line",
  "layer_id": "actors",
  "a": [100, 100],
  "b": [240, 100],
  "color": "#30343e",
  "stroke_width": 3,
  "frame_index": 2
}
```

Отсутствие `frame_index` интерпретируется как старый глобальный объект с обычной покадровой видимостью. Новые GUI/CLI-объекты создаются локальными, если постоянство не запрошено явно. Полный пример схемы выше остаётся концептуальным, не полностью соответствующим текущему прототипу; фактическое состояние описано в [документе 17](17-frame-local-content-v0.4.2.md).
