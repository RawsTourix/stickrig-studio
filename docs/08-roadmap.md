# 08. Дорожная карта разработки

> Принцип: **проектируем и проверяем по вертикальным срезам**, а не пытаемся реализовать все возможности сразу. Даты и сроки здесь намеренно не назначаются. Переход к следующему этапу — после критериев приёмки.

## Этап 0 — Документация и границы продукта

**Результат:** понятная постановка задачи, модель данных, план минимального работающего мультфильма.

- [x] Концепция, цели, творческий сценарий.
- [x] Начальный набор требований и приоритетов.
- [x] Предварительная архитектура и модель данных.
- [x] Эскиз JSON и ИИ/MCP-слой.
- [x] Проверочный сценарий и критерии MVP.
- [ ] Определить окончательную схему v1 для MVP и её валидатор.
- [ ] Проверить выбранный технологический стек на минимальном эксперименте.

**Не начинать здесь полноценный редактор и монтаж.**

## Этап 1 — Технический скелет приложения

- [ ] Создать Python-проект, окружение, автоформатирование и тесты.
- [ ] Реализовать сущности Project / Scene / Layer / Entity / Rig / Track.
- [ ] Сделать сохранение/загрузку JSON и проверку ссылок.
- [ ] Добавить командную модель и Undo/Redo.
- [ ] Создать окно с холстом и рамкой камеры.
- [ ] Тестировать трансформации и round-trip.

**Приёмка:** проект с линией, кругом и стикменом открывается повторно без изменения состояния.

## Этап 2 — Минимальная живая анимация (первый ключевой результат)

- [ ] Стандартный стикмен, FK, перемещение суставов и всей фигуры.
- [ ] Выделение и отображение манипуляторов.
- [ ] Добавление/дублирование/удаление кадров.
- [ ] `hold`, длительность поз, настройка FPS.
- [ ] Onion skin предыдущего кадра без дублирования фона.
- [ ] Предпросмотр воспроизведения и переход между кадрами.
- [ ] Короткий рендер кадров в последовательность изображений.
- [ ] Сборка изображения в видео через FFmpeg.
- [ ] Тесты Undo/Redo и независимости нескольких персонажей.

**Приёмка MVP:** за одну сессию вручную создан, сохранён, заново открыт и экспортирован короткий ролик с двумя стикменами и минимум 12 позами. Отсутствие ИИ, IK и звука не мешает этому.

## Этап 3 — Удобная анимационная студия (V1)

- [ ] Полноценные слои и порядок отрисовки, глаз/замок.
- [ ] Сетка, подразделения, свободный режим и привязка.
- [ ] Работа с диапазонами кадров и несколькими объектами.
- [ ] Камера: независимый zoom, движение по ключам, «вернуться к камере».
- [ ] Onion skin нескольких кадров / выбранных слоёв.
- [ ] Линейная интерполяция, затем опциональная настройка easing.
- [ ] Привязка оружия к кисти; отсоединение при броске.
- [ ] Автосохранение и восстановление.
- [ ] Дополнительные горячие клавиши, контекстное меню и инспектор.
- [ ] Измерить отклик интерфейса и размер файлов на реальных сценах.

**Приёмка:** сцена боя со статичным двухэтажным фоном, движущейся камерой и несколькими персонажами создаётся без ручного переписывания JSON.

## Этап 4 — Конструктор и библиотека (V1+)

- [ ] Кривые Безье, узлы, свободное рисование и составные группы.
- [ ] Изменяемый внешний вид персонажей, геометрия и цвета.
- [ ] Создание пользовательского оружия и якорей/шарниров.
- [ ] Каталог шаблонов, импорт/экспорт отдельных моделей.
- [ ] Режим IK для кистей и стоп.
- [ ] Чёткое разделение asset/instance/override.

**Приёмка:** пользователь создаёт катану и составные нунчаки, сохраняет их, импортирует в другой проект и крепит к руке стикмена.

## Этап 5 — Программное управление и ИИ

- [ ] CLI/API команд ядра и документированная схема.
- [ ] Выборочное изменение сцен по идентификаторам.
- [ ] Атомарный пакет операций, dry-run, проверки revision.
- [ ] Предпросмотр PNG для внешнего клиента.
- [ ] MCP-адаптер и управление разрешениями.
- [ ] Тест: ИИ добавляет векторный фон, не меняя анимации персонажей.

**Приёмка:** внешний инструмент создаёт новый зал с лестницей и дверями, получает его превью, пользователь редактирует результат мышью.

## Этап 6 — Монтаж, музыка и финальный экспорт

- [ ] Отдельный монтажный таймлайн со ссылками на сцены.
- [ ] Импорт музыки и эффектов, несколько дорожек.
- [ ] Обрезка, перемещение, регулировка громкости, fade in/out.
- [ ] Форма волны, маркеры ритма/событий, точная синхронизация.
- [ ] Экспорт с аудио; воспроизводимое поведение длительностей.
- [ ] Возврат в редактор сцены из монтажного клипа без потери монтажа.
- [ ] Проверить работу с лицензиями, кодеками и звуковыми форматами.

**Приёмка:** несколько анимационных сцен сводятся в один ролик, удары синхронизируются со звуком, а правка отдельной позы не разрушает монтаж.

## Что сознательно откладываем

Облако, многопользовательский режим, 3D, реалистичную физику, видеогенерацию по тексту, огромную библиотеку готовых моделей и сложные спецэффекты.

## Правило перед переходом к этапу

1. Показать работающий результат предыдущего этапа.
2. Проверить основные ошибки и сохранность проекта.
3. Обновить документацию по фактической реализации.
4. Не считать плановую функцию уже готовой только потому, что она описана в документации.

## Следующее действие

После ревизии документов начать **Этап 1** с минимальной сцены и сохранения проекта. Не добавлять в первый же коммит всю тяжёлую UI-систему.


## Реализация первого вертикального среза — v0.1 (08.11.2026)

Добавлены пакет Python/PySide6, редактор стикменов с FK-суставами, простые примитивы, кадры с удержанием позы, onion skin, слои (фон/персонажи), статичная камера, JSON, Undo/Redo, PNG/MP4, тестовый проект. Включены CLI для просмотра/валидации проекта и безопасных атомарных правок по JSON с проверкой ревизии; **MCP-сервера пока нет**. Есть автоматизированные тесты и CI smoke-тест графического окна. Это **рабочая реализация первого приближения**, а не окончательная приёмка этапов 1–2: требуется ручное тестирование GUI на Windows и обратная связь по эргономике. Полная актуальная матрица функций и ограничений — [11 — Prototype v0.1](11-prototype-v0.1.md).
