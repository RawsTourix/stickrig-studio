# 14. Итерация v0.4 — размещение панелей по примеру GraphicsGale

> Статус: реализовано в ветке `feat/workspace-layout-blank-frames-v0.4`; окончательная ручная проверка на Windows и разных DPI необходима.

## Исходные замечания

1. Внизу **Frames** требуется одна компактная кнопка `+`. При её нажатии создаётся **пустой кадр**, а не копия предыдущей позы.
2. В нижней части *рабочей области сцены* нужна отдельная узкая строка, как в GraphicsGale: координаты слева, масштаб вида — справа.
3. Управление воспроизведением должно быть отдельной **узкой и центрированной полосой**, изначально выше **Elements**.
4. Playback должен быть переставляемым *в том числе вертикально относительно Elements*: раньше был `QToolBar` и не мог находиться как вложенная док-панель поверх другой.

## Новая компоновка

```text
┌─ Frames ────┬──────────────────────── Canvas ─────────────────────────┬─ Inspector ─┐
│ miniature   │            редактируемые персонажи, камера             │            │
│ miniature   ├─────────────────────────────────────────────────────────┤            │
│ miniature   │ Cursor X: … Y: …  Selected X: … Y: …          − 100% + Fit│            │
│             ├───────────────────── Playback ─────────────────────────┤            │
│             │                 ◀  ▶ Play  ▶|   Frame   FPS            │            │
│             ├────────────────────── Elements ─────────────────────────┤            │
│ +           │            библиотека стикменов и примитивов           │            │
└─────────────┴─────────────────────────────────────────────────────────┴────────────┘
```

Схема условная: каждый QDockWidget перемещается, открепляется и изменяет размер через Qt. Playback и Elements теперь **оба QDockWidget в нижней зоне**, разделённые вертикально через `splitDockWidget`; Playback по умолчанию сверху. Это устраняет ограничение прежнего `QToolBar` на взаимное размещение.

## Полоса состояния холста

Состоит из:
- координат курсора в системе сцены (`+X` вправо, `+Y` вниз);
- координат выбранного элемента: корень стикмена, выбранный сустав или центр примитива;
- реального масштаба редакторского окна (viewport zoom), кнопок `−`, `+`, `Fit`.

Полоса закреплена за холстом, поэтому **не перекрывает рисунок**, остаётся с холстом при любом расположении доков и не влияет на экспорт. Художественный `camera.zoom` не меняется от её кнопок.

## Пустой кадр против дублирования

Введена новая команда ядра `insert_blank_frame(project, after)`:

- `+` под Frames добавляет **пустой анимационный кадр после текущего**.
- «Insert blank frame after» в контекстном меню создаёт тот же тип кадра.
- «New blank frame at end» вставляет пустой кадр в конец.
- Быстрая кнопка дублирования и `Ctrl+D` **продолжают копировать** (удерживать) состояние предыдущего кадра.
- Сохранённые фоновые ресурсы остаются на всех кадрах: «пустой» означает **без существующих анимированных персонажей**, а не удаление общего фона.
- Новая сущность, созданная на кадре с индексом больше нуля, появляется не раньше этого кадра.

Для этого добавлено свойство `visible` с покадровыми hold-ключами для отдельных сущностей. При вставке пустого кадра предыдущая анимация остаётся прежней, а видимость следующего кадра **восстанавливается**. Новое поле расширяет существующий формат JSON без изменения несовместимой версии схемы. Старые проекты без `visible` ведут себя как прежде.

## Приёмка

- [ ] Тест Windows: воспроизведение по центру узкого дока **выше** Elements.
- [ ] Тест Windows: перетащить Playback ниже Elements и обратно, сохранить проект, открыть его, получить ту же раскладку.
- [ ] Статусная строка остаётся непосредственно под холстом при перемещении/масштабировании других панелей.
- [ ] Координаты следуют за курсором, выбранный сустав показывает свои координаты, процент зума не смешивается с камерой.
- [ ] `+` создаёт пустой кадр с общим фоном, но без предыдущих персонажей.
- [ ] Быстрое дублирование сохраняет персонажей и позу.
- [ ] Проект можно сохранить/открыть, история Undo/Redo корректна.
- [ ] Рендер PNG/MP4 и GUI согласованы по видимости объектов.
- [ ] Прокрутка миниатюр остаётся ленивой.

## ИИ/CLI

Через валидируемый JSON-пакет добавлены команды `insert_blank_frame` (`after`), `set_entity_visibility` (`id`, `frame`, `visible`), и необязательное поле `frame` для `add_stickman`. Например:

```json
{
  "expected_revision": 0,
  "operations": [
    {"op": "insert_blank_frame", "after": 0},
    {"op": "add_stickman", "id": "second", "position": [280, 250], "frame": 1}
  ]
}
```

Это позволяет ИИ воспроизвести команду интерфейса без обхода проверок и с атомарностью пакета. MCP-сервер по-прежнему не реализован.
