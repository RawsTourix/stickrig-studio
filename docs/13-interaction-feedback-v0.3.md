# 13. Развитие интерактивности v0.3

> Статус: реализовано для версии v0.3; проверено автоматическими тестами. Жесты на реальном Windows-тачпаде требуют пользовательского тестирования.

## Исходная обратная связь

- Чувствительность перемещения должна плавно зависеть от масштаба сцены.
- Процент зума нужен непосредственно в нижнем правом углу рабочей области.
- Управление предпросмотром должно быть отдельной узкой полосой.
- При выборе элемента — полупрозрачный «призрак» под курсором перед размещением.
- Frames: контекстные меню на кадре и пустой области, быстрые кнопки скрытия/дублирования/удаления, изменение порядка кадров перетаскиванием за отдельную область.
- На будущее — международный интерфейс на английском и русском.

## Навигация и зум

Масштаб **рабочего окна** не изменяет художественный масштаб камеры или экспорт. Чувствительность панорамирования определяется плавной ограниченной функцией от текущего масштаба просмотра:

`s = clamp(1 / sqrt(view_scale), 0.4, 3.2)`

Это **экспериментальная кривая**. При крупном масштабе перемещение точнее, при мелком — быстрее. Изменения прокрутки с дробными остатками накапливаются, чтобы небольшие движения тачпада не пропадали из-за целочисленных Qt scrollbars. Свайп/обычное колесо — панорамирование; Ctrl+колесо — изменение зума. Отдельный оверлей на сцене показывает точный процент viewport zoom (не camera zoom), кнопки ± и Fit.

Если Windows-драйвер посылает другой тип жестов, пользовательская проверка определит необходимость дополнительной обработки native-gesture событий.

## Призрак размещаемого объекта

Выбор Stickman, Line, Rectangle или Ellipse включает полупрозрачный предпросмотр под указателем. Он исчезает при уходе курсора, переключении на Select, начале взаимодействия/воспроизведения. Он не сохраняется в проект, не попадает в экспорт и рисуется отдельно от статичного фона.

Для сохранения отзывчивости **обновляется только preview-геометрия** во время обычного перемещения курсора, а не пересоздаётся вся сцена.

Для примитивов предпросмотр использует стартовый размер до начала перетаскивания; при создании мышью появляются изменяемые границы текущей фигуры.

## Полоса воспроизведения

Панель Playback — отдельный `QToolBar`, расположенный снизу, с командами начального/соседних кадров, Play/Pause, текущим номером кадра и FPS. Он не привязан к панели Frames; панель можно закрывать или перемещать без потери управления воспроизведением.

## Frames: управление кадрами

Стандартный новый проект начинается с **одного** кадра. Кадры имеют порядок `0..N-1` в JSON; в UI отображаются как `1..N`.

- **Правый клик по пустой области:** добавить в конце, дублировать текущий.
- **Правый клик по кадру:** скрыть/показать, дублировать, вставить после, переместить выше/ниже, удалить.
- **Кнопки на кадре:** видимость при воспроизведении (●/○), дублирование (D), удаление (×).
- **Захват ≡ слева:** drag-and-drop для перестановки.
- **Скрытие:** кадр остаётся в редакторе и доступен для правки, но исключается из воспроизведения **и MP4-экспорта**. Нельзя скрыть все кадры.
- **Дублирование:** поскольку пока используется модель hold-keyframes, вставка после кадра наследует его состояние. Это равнозначно копированию текущей позы.
- **Перемещение:** меняется настоящий порядок временных состояний. Обновляются ключевые значения всех имеющихся дорожек, а не только текст миниатюры.
- **Удаление:** не должно изменять состояние оставшихся кадров, даже если удалённый кадр содержал ключ, действовавший на следующие.
- **Undo/Redo:** действует на вставку, удаление, перемещение и видимость кадров.

### Производительность

Список — `QListWidget` с одним delegate для отрисовки быстрых кнопок и захвата, **без отдельных виджетов на каждый кадр**. Миниатюры создаются только для видимого диапазона по одному кадру за цикл Qt. Формат предпросмотра — 128 px по ширине. При перемещении кадра модель пересчитывает только границы изменения hold-треков, а не растровые изображения всех кадров.

Большие проекты всё ещё потребуют профилирования: Python/Qt, 100 000 кадров и сотни независимых дорожек — не заявленная проверенная нагрузка.

## AI / CLI

`apply_patch` поддерживает четыре новые валидируемые операции:

```json
{
  "expected_revision": 0,
  "operations": [
    { "op": "insert_frame", "after": 0 },
    { "op": "set_frame_hidden", "frame": 1, "hidden": true },
    { "op": "move_frame", "source": 1, "target": 0 }
  ]
}
```

Сначала можно вызвать CLI с `--dry-run`. Неисправная операция отменяет **весь** пакет. Структурные изменения кадров отвергаются, если есть заблокированные слои.

## Локализация (подготовка)

3. Поддержать EN и RU без перезапуска или явно задокументировать требование перезапуска.
4. Проверить отсутствие обрезания длинных русских подписей в док-панелях.
5. Переводить руководство и сообщения о доступных горячих клавишах.

## Проверить вручную на Windows

1. Панорамирование свайпом на разных масштабах; сравнить низкий и высокий zoom.
2. Процент справа снизу корректно обновляется после Ctrl+скролла и Fit.
3. Панель Playback можно двигать отдельно от Frames; комбинации клавиш работают.
4. Полупрозрачный Stickman следует за курсором; после клика появляется настоящий объект.
5. В Frames правая кнопка по пустой области и по кадру вызывает разные меню.
6. Быстрые кнопки не инициируют перетаскивание, оно начинается **только за ≡**.
7. Сделать 3 разные позы, переставить их и проверить предпросмотр, потом сохранить/перезагрузить.
8. Скрыть второй кадр: он остаётся в списке, а воспроизведение и экспорт пропускают его.
9. Undo/Redo возвращает последовательность и состояние скрытия.
10. Несколько десятков кадров — проверить прокрутку миниатюр и нагрузку ЦП.

## Ограничения

- Перестановка пока рассчитана на hold-keyframe, а не на интерполяцию по кривым.
- Нельзя копировать несколько кадров одновременно.
- Отдельного свойства длительности удержания позы ещё нет.
- Миниатюры и кнопки — рабочая версия; окончательный UX после пользовательского теста.
